# 1. DOCUMENT STATUS

**Project:** Zaynahs Ecosystem  
**Document Type:** Atomic Production Engineering Specification  
**Architecture:** Single Ecosystem / Trusted Multi-Device / Local-First / Event-Ledger  
**Status:** Authoritative Engineering Contract

This document defines how the Zaynahs Ecosystem must be designed,
implemented, tested, secured, synchronized and maintained.

This is not a prototype specification.

The implementation must be production-oriented and must avoid:

- fake functionality
- demo-only functionality
- hard-coded secrets
- silent data loss
- silent data overwrite
- duplicated business engines
- duplicated shared UI
- isolated fixes for global data problems
- insecure permission checks
- direct database access from UI
- direct filesystem access from UI
- low-level WebRTC logic inside UI widgets
- destructive financial history edits
- last-write-wins for financial/inventory events
- unnecessary polling
- unnecessary memory usage
- unnecessary animations
- unnecessary architecture complexity

# 2. ABSOLUTE NO-MULTI-BRANCH RULE

## 2.1 There is NO branch architecture

The ecosystem must NOT contain:

- `branch`
- `branch_id`
- branch manager
- branch permissions
- branch reports
- branch inventory
- branch wallet
- branch settings
- branch switching
- branch transfers
- branch-scoped users

Do not create branch architecture indirectly.

Do not rename a branch into:

- store
- site
- location
- warehouse
- outlet

and then use it as a hidden branch system.

A device is NOT a branch.

A physical location is NOT a branch.

# 26. PERMISSION RESOLUTION

Permission evaluation:

```text
DENY BY DEFAULT
       ↓
ROLE TEMPLATE
       ↓
ROLE PERMISSIONS
       ↓
USER OVERRIDES
       ↓
VALUE LIMITS
       ↓
FINAL DECISION
```

Example:

```text
Role:
Cashier

pos.discount.apply = true

User Override:
pos.discount.max_percent = 5
```

Result:

```text
Discount <= 5%  → ALLOW
Discount > 5%   → DENY
```
